# Участие в cybOS

Спасибо за помощь в развитии CicadaFarm и RobotCYB. Начните с [README](README.md) и выберите компонент в [каталоге](ecosystem.json).

## Куда вносить изменения

В этом репозитории находятся каталог, фиксированные ревизии, bootstrap и статическая карта. Код рабочего стола находится в [CybOS-demo](https://github.com/c1cad4/CybOS-demo), серверный API — в [CybCore](https://github.com/c1cad4/CybCore). У каждого компонента свои требования и проверки.

## Рабочий процесс

1. Опишите конкретную проблему или сценарий. Для ошибки приложите воспроизведение, ожидаемое поведение и окружение.
2. Создайте ветку с одной связной задачей. Сохраните чужие локальные изменения.
3. Внесите изменение и обновите соответствующую документацию.
4. Выполните проверки компонента; при изменении API проверьте интегратор.
5. Откройте PR с объяснением результата и фактической проверки.

Проверка этого репозитория из его корня:

```bash
python3 -m unittest discover -s tests -v
```

Изменения карты дополнительно проверяйте в браузере: поиск, фильтры, отсутствие совпадений, загрузка каталога и узкое окно. Подготовка всей экосистемы описана в [DEVELOPMENT.md](docs/DEVELOPMENT.md).

## Каталог и ревизии

`ecosystem.json` описывает роль, статус, команды и фактические зависимости. `ecosystem.lock.json` фиксирует доступные коммиты соседних репозиториев. Обновляйте pin после публикации и проверки соответствующего компонента. Статус `planned` сохраняйте, пока нет проверяемого рабочего сценария.

## Сторонний код

Перед переносом кода проверьте лицензию, совместимость и необходимые уведомления. Укажите источник и назначение зависимости. Для реальных измерений и результатов сохраняйте источник; демонстрационные данные помечайте явно.

## Описание PR

Назовите решаемую проблему, объясните новое поведение и перечислите выполненные проверки. Если сборка требует недоступного SDK, оборудования или внешнего сервиса, укажите это прямо. Изменения релизов и прошивок оформляйте отдельной задачей.
